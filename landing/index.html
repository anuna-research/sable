sable · biometric proof research

Explore biometric matching with zero-knowledge proofs.

Experimental Halo2 circuits check biometric and liveness relations. The current browser demo sends embeddings and images to a server, which generates the proof. This is centralized biometric processing, not on-device-only privacy or authenticated physical capture.

Current implementation

A research result is not an identity credential.

Operator-provisioned credentials authorize access to the research API. The server requires complete embedding and liveness inputs and verifies proofs against its own enrollment, threshold and single-use challenge state. These checks do not attest a device, camera or human identity.

Local research builds remain available. Registry publishing and the deployment image are on a security release hold. Existing remote services and binaries have not been changed by this repository remediation.

Actual data boundary

The server currently receives biometrics.

Browser capture

Enrollment sends an embedding. Authentication sends a live embedding, four flash frames and any enabled eye crops. The browser is an untrusted input source.

Server processing

The server converts features, extracts measurements and generates proofs. Enrollment lookup expires after 15 minutes; active requests may retain copies longer.

Verifier policy

The proof must match a stored template, threshold, liveness result, challenge digest and expiry. Public fields are not accepted as authorization by themselves.

Missing provenance

A valid relation does not establish a camera observed a live person. Trusted sensor or hardware-backed capture attestation remains unimplemented.

Security limitations

What this build does not promise.

Is this ready for production?
No. Critical and high remediation remains incomplete. Do not use it for real access control, identity decisions or public deployment. Passing unit tests is not independent security approval.
Does biometric data stay on my device?
No. The current demo sends embeddings and images to the server. Proof privacy does not hide them from that server, its operator or TLS terminator. Client-side proving and a commitment/proof-only server interface remain required.
Does liveness prove physical presence?
No. Software liveness is experimental presentation-attack risk reduction. Thresholds need population and attack testing. A malicious prover with a template can fabricate satisfying private measurements without capturing a person.
Are mobile, offline P2P and government credentials available?
No. The unsafe legacy APIs are withdrawn. The Noise replacement is private test code; attestation binding and transport integration are incomplete. Hardware keystore and selective-disclosure integration are not available controls.
Does Halo2 mean there is no trusted setup?
Not in this implementation. It uses BN254 KZG with locally generated research parameters. Production ceremony provenance and the key lifecycle have not been established.

The source includes the red-team findings, current threat model and remediation evidence under docs/security/. The prior production recommendation is withdrawn.
